# เตรียมฟอนต์และตรวจสระไทย

1. เก็บข้อความแปลต้นฉบับเป็นไทยอ่านได้ และสำรองไฟล์ก่อนเสมอ แปลงเฉพาะสำเนาสำหรับ pack
2. ใช้ Mapping.json คู่กับ ThaiPUAStarter-Bold.ttf ห้ามใช้ Mapping จากฟอนต์อื่นปนกัน
3. ทดสอบข้อความแต่งเอง เช่น `กุ้ง ปู่ ผู้กล้า น้ำ เก่ง` และชุดสระล่าง/สระบน/วรรณยุกต์หลายแบบด้วย preview.html
4. เมื่อผล mapping ผ่าน audit ให้รวบรวม glyph IDs ของข้อความที่จะแพ็ก ตรวจว่า native font ของเกมมี IDs เหล่านี้ครบ TTF มีครบไม่ได้แปลว่า atlas ในเกมมีครบ
5. หากเกมใช้ bitmap atlas ต้อง rasterize glyph ลง atlas และสร้าง metrics/native descriptor ให้ตรงรูปแบบเกม ด้วยเครื่องมือที่รองรับเกมนั้น ชุดเริ่มต้นนี้ยังไม่ทำขั้นตอน native building ให้
6. ตรวจพื้นที่เหนือ/ใต้ baseline, glyph bounding box, offsets, advance และพื้นที่ตัดขอบของกล่องข้อความ อย่าแก้โดยเลื่อนสระทุกตัวเท่ากัน เพราะรูปอักษรและบริบทต่างกัน
7. สำหรับ Revelations ที่ตรวจในโครงการเดิมเป็น white RGB + alpha ใน BC3 atlas ตรวจภาพที่ decode กลับแล้วทั้งสีและ alpha การดู alpha อย่างเดียวไม่ยืนยันสีซับในเกม อย่านำสูตร native นี้ไปใช้กับเกมอื่นโดยยังไม่ตรวจ
8. ทดสอบเมนู ซับหลายบรรทัด ขนาดอักษรเล็ก/ใหญ่ สระล่าง และวรรณยุกต์ในเกมจริง เก็บภาพก่อน/หลัง และตรวจไฟล์ export กลับว่า IDs/tokens/จำนวนรายการเดิมไม่เปลี่ยน

## คำถามที่พบบ่อย

**PUA ใน Notepad เป็นตัวแปลก ๆ?** ปกติถ้าไม่ได้เลือกฟอนต์ที่ตรงกัน ใช้ HTML preview ที่ให้ หรือโปรแกรมที่เลือกฟอนต์นี้ได้

**แปลงแล้วเกมยังสระขาด?** ต้องดู native atlas/descriptor และขอบพื้นที่แสดง ไม่สามารถวินิจฉัยจากข้อความอย่างเดียว ส่งภาพอาการ ชื่อเกม และขั้นตอนทำฟอนต์ประกอบ

**ใช้กับ CSV จากเครื่องมือแปลได้ไหม?** ยังไม่มี CSV adapter อย่าแปลงทั้งไฟล์ ต้องมี adapter ที่เลือกเฉพาะคอลัมน์แปลและตรวจ schema/IDs/encoding/บรรทัดก่อนใช้

**ใช้กับเกมอื่นได้ไหม?** ใช้เป็นต้นแบบกระบวนการได้ แต่ต้องเตรียมฟอนต์และ importer ของเกมนั้นเอง ชุดนี้ไม่รับประกันความเข้ากันได้กับเกมอื่น
